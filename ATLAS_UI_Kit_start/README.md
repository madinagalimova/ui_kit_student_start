# ATLAS UI Kit — стартовый проект для студентов

## Ситуация
Команда веб-разработки создаёт панель Help Desk. Макет страниц уже согласован, но в коде встречаются несогласованные цвета, отступы и разные стили одинаковых элементов. Вы отвечаете за техническую основу UI Kit.

## Файлы
- `index.html` — готовая разметка демонстрационной страницы; в самостоятельной работе дополните её.
- `css/tokens.css` — примитивы, светлые семантические значения и компонентные токены; тёмную тему реализуете вы.
- `css/components.css` — готовая геометрия страницы и частичная реализация кнопки; остальные компоненты и состояния реализуете вы.
- `js/theme.js` — заготовка переключения тем, требуется завершить и проверить.
- `Ожидаемый_вид_...png` — визуальные ориентиры (эталон не требует попиксельного копирования).

## Запуск
Откройте эту папку в VS Code/IntelliJ IDEA. В терминале из папки проекта выполните:

```bash
python -m http.server 5500
```

В браузере откройте http://localhost:5500. Допускается Live Server.

## Что делать
Работайте строго по PDF/DOCX с практической работой. Ищите в коде пометки `TODO`.
Сначала создайте тёмную тему, затем кнопки, поля, уведомления; проверьте `Tab` и режимы на заданных ширинах. В конце выполните самостоятельную часть: компактный режим и предупреждение.

## Что сдавать
Исходники проекта, `README.md` с архитектурой токенов и тестами, 4 скриншота (светлая, тёмная, компактная, ширина 320 px), краткое объяснение двух проектных решений.

## Ограничения
Без Bootstrap, Tailwind, UI-библиотек, inline-цветов, `!important` для обхода недостатков архитектуры. Свои токены добавлять можно; не удаляйте семантику HTML и доступные подписи.

## Выполненная работа (отчёт)

### Архитектура токенов

Система построена по трём уровням:

1. **Примитивы** (`--base-*`) — конкретные значения без привязки к роли.
2. **Семантические токены** (`--color-*`) — описывают назначение в интерфейсе (фон, текст, границы, действия, уведомления).
3. **Компонентные токены** (`--button-*`, `--control-*`) — связывают семантику с элементами.

Цепочка одного токена:
`--base-blue-700` → `--color-primary` → `--button-bg-primary` → `.button--primary { background: var(--button-bg-primary) }`.

### Что реализовано

- Тёмная тема: автоматическая (по системе) и ручная (`data-theme="dark"`).
- Переключатель темы: `auto / light / dark`, сохранение в `localStorage`.
- Кнопки: primary, secondary, ghost + hover, active, disabled, focus-visible.
- Поля ввода: input, select, focus, disabled, `[aria-invalid="true"]`.
- Уведомления: info, success, error, warning.
- Компактный режим: переключатель плотности, сохранение в `localStorage`.

### Ответы на вопросы

**1. Почему плотность задаётся компонентными токенами?**
Потому что плотность влияет на конкретные элементы (кнопки, поля, уведомления), а не на всю страницу. Если менять размеры через компонентные токены (`--button-height`, `--control-height`), то достаточно переопределить их в одном месте, и все компоненты автоматически станут компактнее. Не нужно создавать отдельные CSS-правила для `.button` и `.input` в компактном режиме.

**2. Почему тёмная тема не должна хранить прямые цвета внутри `.button`?**
Потому что тёмная тема — это про смену **ролей** (фон, текст, границы), а не про отдельные компоненты. Если прописать жёсткий цвет внутри `.button--primary`, то при смене темы эта кнопка останется старой, и интерфейс будет выглядеть сломанным. Компонент должен использовать `var(--button-bg-primary)`, а значение этой переменной уже меняется в `tokens.css` в зависимости от темы.
